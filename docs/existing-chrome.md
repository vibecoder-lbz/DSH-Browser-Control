# 免配对连接与副本接管

`dsh-browser-use 0.5.0` 的已有 Chrome 模式默认自动连接，并且只控制复制后的标签页。DSH 插件安装并运行后，在 Chrome 加载新版扩展即可使用，不再填写配对码。

## 安装

如果当前 DSH 已安装此插件，只需要更新到 0.5.0，再在 Chrome 中加载 / 重新加载 [chrome-extension](../chrome-extension/) 目录。新版扩展使用固定身份，旧版本升级时若 Chrome 未能直接重载，应移除旧的 DSH 扩展后重新加载该目录。

新电脑需要先安装 DSH 侧工具插件：

```powershell
dsh plugin --profile web add "D:\project\dsh_plugin\dsh-browser-use-0.5.0.tgz"
```

已有旧版组合包时，先用 `dsh plugin --profile web remove dsh-browser-use` 移除，再添加新版。将 `web` 替换为实际 profile；如要求重启，重启原来的 DSH。

Chrome 扩展加载：

1. 打开 `chrome://extensions`，打开“开发者模式”。
2. 选择“加载已解压的扩展程序”，选择 [扩展目录](../chrome-extension/)。也可将扩展 ZIP 解压到固定目录后加载。
3. 扩展默认开启自动连接。工具栏弹窗显示连接状态，并提供暂停 / 恢复按钮。

需要 Chrome 125+；兼容的 Edge 可以通过 `edge://extensions` 加载。无需开启浏览器远程调试端口，无需另起 MCP 服务。浏览器扩展本身负责连接，Agent 工具由运行中的 DSH 插件提供；仅安装扩展、但没有运行 DSH 时不会凭空获得 AI 控制能力。

默认本地桥地址是 `ws://127.0.0.1:19876/extension`。DSH 插件启动时自动监听此地址，扩展持续自动重连。只有使用自定义端口时，才需要在扩展高级设置中填写相同的本地地址；没有配对令牌字段。

## 如何接管

直接告诉 Agent 目标，例如：

> 复制并接管当前 Chrome 中的 JumpServer 页面，在副本中查看资产。

```jsonc
browser_connect({ "action": "select", "query": "JumpServer", "screenshot": true })
```

过程如下：

1. 按原页面的网址 / 标题匹配目标。受控副本不会参与默认关键词匹配，避免同名歧义。
2. 按源标签页 ID 查找已有副本。重复接管、换会话、连接重建和插件热更新优先复用它，不按会话另建一份。
3. 没有副本时，在源窗口以 `active:false` 创建同网址的后台标签页，不新开窗口、不移动标签页、不切换活动标签页。
4. 控制时给副本加上 `【被接管】` 标题、`DSH · 被接管` 标签组和右上角角标。
5. 点击、输入和终端命令只发往副本；整个操作不发出窗口激活请求。

同一个源标签页只有一个控制副本。其他会话占用它时返回占用错误，不再复制；释放后其他会话可以接管这个副本。多个不同源页面的操作会顺序执行。

扩展本地保存源与副本的关系，并在重载时结合页面的随机身份标识验证后复用。旧副本仍在但身份不能可靠验证时，会提示处理旧副本，避免静默再复制。旧版已经产生的额外页面不会被自动关闭，防止丢失其中的输入或远程会话。

Chrome 原生复制没有 `active:false` 参数，因此本版本改用后台打开同网址。它保留同一浏览器 profile 的登录状态，不复制导航历史或页面运行内存。

匹配规则保留完整网址、完整标题、网址关键词、标题关键词和全部查询词匹配。“JumpServer / 堡垒机”可识别常见 `/luna` 与 `/koko` 入口。没有唯一匹配项时返回候选，不会猜测。

```jsonc
browser_connect({ "action": "list" })
browser_connect({ "action": "select", "tabId": "chrome-123" })
```

列表中的 `controlled` 标明是否副本，`sourceTabId` 指向原页面。返回结果也会说明源页面与受控副本的 ID。原页面不能被调试附加或通过关闭工具移除。一个副本同时只能由一个会话控制。

## 副本能保留什么

副本使用相同网址和浏览器 profile 的网站登录。**它不等于克隆页面运行内存**，不复制导航历史、未提交表单、临时页面状态、正在运行的 JavaScript 或 WebSocket / SSH 连接。

副本与原页面使用同一 Chrome profile，共享 Cookie、localStorage 和服务器账号。因此：

- 在副本填表不会改写原页面输入框，但提交后仍会修改同一后台系统。
- 在副本退出网站登录可能使原页面也退出。
- 这是浏览器界面的分离，不是账号、服务器数据或 Kubernetes 集群的隔离。

不能把副本描述为“完全一样且完全独立”。

## JumpServer

复制 JumpServer 的 Luna 页面后，可能需要在副本中重新选择资产并打开 Web SSH。原页面里已经连接的“中核战舰”等终端，其现有 SSH 会话不能保证迁移到副本。插件不会为了继续旧终端而退回原页面输入命令。

副本中打开正确的资产后，继续使用终端工具：

```jsonc
browser_terminal({ "action": "list", "screenshot": true })
browser_terminal({ "action": "type", "terminalId": "terminal1", "text": "kubectl config current-context" })
browser_terminal({ "action": "press", "terminalId": "terminal1", "key": "Enter" })
browser_terminal({ "action": "wait", "terminalId": "terminal1", "timeoutMs": 1000, "screenshot": true })
```

输入文字和回车分开发送；有多个终端时明确选择。Canvas / WebGL 可能需要图片模型读取截图。命令派发并不证明远端执行成功，断连也不等于撤销已提交命令。详见 [JumpServer / Kubernetes 指南](./jumpserver-kubernetes.md)。

## 接管标识与空白副本

副本被接管时会添加 `【被接管】` 标题前缀和右上角角标。0.5.0 修复了页面标题初始为空时的标识刷新死循环：旧版可能让 JumpServer 副本卡在只剩“【被接管】”的空白状态，并同时阻塞调试连接释放。新版对空标题、纯空白标题和 SPA 动态标题都只维护一个前缀，普通页面更新不会反复触发标识刷新。

标记脚本超时只影响角标显示，不会阻塞调试连接建立或释放。如果旧版已经留下卡死的空白副本，关闭该标签页后重新选择原页面即可；原页面本身没有受到影响。

某些 Chrome 版本不会绘制被其他标签页遮住的后台页面。这时截图请求在短预算后返回 `screenshotNotice`，后续请求直接说明不可用，不反复等待或自动切换标签页。DOM 读取、表单与可读终端操作仍可继续。

如果 JumpServer 终端只有 Canvas / WebGL 画面且没有可读 DOM，截图不可用时无法自动核对命令结果。需要你手动选中标记的副本供视觉检查，插件不会擅自切到它。Chrome 自带的调试权限提示仍可能在首次连接时出现，这是浏览器自身界面。

## 释放控制

```jsonc
browser_connect({ "action": "disconnect" })
browser_close({})
```

这两个操作只断开副本调试连接并移除“被接管”标识，保留副本与原页面。取消工具、闲置超时和卸载也会释放标识与控制。需要关闭副本时显式调用 `browser_tabs` 的 `close`；原标签页不能通过本插件关闭。

Chrome 自带的调试权限提示由浏览器显示，扩展不能隐藏它。取消该提示或使用冲突的 DevTools 会断开当前控制。

## 连接来源与范围

本地桥仅绑定 `127.0.0.1`，严格校验 Host 与固定扩展的 `chrome-extension://` Origin，并要求 v2 身份握手。普通网页、其他扩展 ID、缺少来源的连接和旧版令牌 URL 会被拒绝。这不是关闭所有检查后的开放 CDP 端口。

这是同一台电脑的用户级控制边界；能够在本机运行任意进程的用户不属于网页 Origin 机制的隔离对象。不要把端口开放到外网。

扩展请求标签页、调试、定时重连、分组和脚本权限；HTTP(S) 脚本权限仅用于在受控副本注入 / 移除角标与标题标识。没有对外网页消息入口。受保护的 Chrome 内部页面与浏览器策略禁止的目标不可接管。

## 排查

- 扩展等待连接：确认新版 DSH 插件正在运行，未暂停扩展；默认无需配置。
- 原旧版还在：移除旧扩展并加载新版目录；刷新旧页面不会更新扩展后台。
- 端口冲突：同一默认端口只能由一个 DSH profile 提供服务。需要多个 profile 时修改 `bridgePort`，并在扩展高级设置中修改本地地址。
- 页面状态不一致：副本是同网址后台页面，不继承表单、导航历史或运行内存。重新在副本导航到所需界面；不会直接操作原页面。
- 副本只有“【被接管】”或空白：旧版空标题标识循环。关闭该副本，更新扩展到 0.5.0 后重新选择原页面。
- 副本尚未打开终端：先在副本打开正确的 JumpServer 资产。
- 配置原生浏览器中断：重新选择源页面，插件会复用或重建受控副本。
