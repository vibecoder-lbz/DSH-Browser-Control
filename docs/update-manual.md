# DSH 浏览器控制插件更新与使用手册

适用版本：**0.5.0**  
更新日期：2026 年 11 月 13 日  
适用环境：Windows、Chrome 125 及以上、DSH 0.2.2-rc.1、Node.js 24.9.0 及以上。

本手册面向已安装过旧版插件的用户，也包含首次安装、更新验证、日常使用和故障处理。

## 1. 先看你当前需要做什么

本次会话中，**这台电脑的 DSH 插件已经升级并启用为 0.5.0**。你主要需要确认 Chrome 扩展也更新为 0.5.0。

- 如果 Chrome 加载的是项目中的 [chrome-extension 目录](../chrome-extension/)，直接到 `chrome://extensions` 点击该扩展的“重新加载”，然后确认版本。
- 如果加载的是先前 ZIP 的解压目录，先用新版 ZIP 更新那个目录，再点击“重新加载”。仅下载 ZIP 或刷新 JumpServer 页面不会更新扩展。
- 如果在另一台电脑使用，需要同时安装 DSH 插件和 Chrome 扩展，按第 3、4 节执行。

**更新后无需填写配对码。** 前提是 DSH 已启动，并运行对应的浏览器控制插件。

## 2. 两部分组件与本次变化

### 2.1 需要区分的组件

| 组件 | 安装位置 | 作用 | 如何确认版本 |
| --- | --- | --- | --- |
| DSH 插件 `dsh-browser-use` | DSH 当前 profile，例如 `web` | 提供 Agent 的浏览器工具，并启动本地连接服务 | 在 DSH“插件”页面查看组合包版本 |
| Chrome 扩展“DSH 当前标签页控制” | 当前 Chrome 浏览器配置 | 连接已有网页、创建控制副本、显示接管标识 | 在 `chrome://extensions` 中点击该扩展“详情” |

更新其中一项，不会自动更新另一项。两部分都使用 **0.5.0**，才能完整应用本次修复。

### 2.2 0.5.0 的行为

| 项目 | 更新后的行为 |
| --- | --- |
| 连接方式 | 扩展自动连接本机 DSH，不填写令牌 |
| 图标 | DeepSeek 蓝色鲸鱼 |
| 副本数量 | 每个源标签页复用一个控制副本；重复接管、重连和换会话不再各建一份 |
| 会话占用 | 副本被其他会话使用时提示占用，不创建第二份 |
| 窗口 | 在源页面所在窗口后台创建副本，不新开自动化窗口 |
| 焦点 | 不自动激活标签页、不移动标签页、不切换窗口 |
| 接管标识 | 副本标题显示“【被接管】”，页面右上角显示角标，并有 DSH 标签组 |
| 断开 | 释放控制并移除接管标识，保留页面 |
| 后台截图 | Chrome 不绘制后台页面时明确提示，不为获取截图而抢焦点 |
| 配置编辑 | 新增 browser_editor，按 YAML 路径生成缩进和层级；先读取、预览并校验，再应用草稿，不自动发布。详见 [结构化编辑说明](./structured-editing.md) |
| JumpServer 空标题 | 修复页面初始标题为空时接管标识反复改写标题、导致副本空白卡死的问题；标识更新超时不再阻塞建立或释放调试连接 |

原页面与副本共享网站登录和后台账号数据。副本中的提交、发送或部署仍会影响同一个后台系统。

## 3. 更新 DSH 插件

如果当前电脑已确认是 0.5.0，可以跳过本节。

### 3.1 准备安装包

使用 [DSH 插件安装包](../dsh-browser-use-0.5.0.tgz)。本项目目录中的位置为：

```text
D:\project\dsh_plugin\dsh-browser-use-0.5.0.tgz
```

在其他电脑上，请将后续命令中的路径改为实际保存位置。

### 3.2 从旧版升级

先结束当前浏览器自动化任务，或在对话中要求 Agent“释放当前网页控制”。释放连接不会撤销已提交的网页操作，也不会自动回滚远程命令。

打开 PowerShell，**分两次执行**以下命令：

```powershell
dsh plugin --profile web remove dsh-browser-use
```

确认移除成功后，再执行：

```powershell
dsh plugin --profile web add "D:\project\dsh_plugin\dsh-browser-use-0.5.0.tgz"
```

`web` 是当前示例 profile。如果你使用其他 profile，必须将两条命令中的 `web` 同时替换为实际名称。

首次安装只需要执行 `add` 命令，不需要先移除。

### 3.3 判断是否需要重启

| 安装结果 | 下一步 |
| --- | --- |
| 已应用 / `applied` | 插件已经生效，继续更新 Chrome 扩展 |
| 需要重启 / `restart-required` | 重启原来的 DSH 进程，再确认插件版本 |
| 失败 / `failed` | 按错误提示处理，不把“文件已下载”视为启用成功 |

不需要为这项插件启动另一个 Web 服务。重启 DSH 时沿用原来使用的启动方式。

### 3.4 提示找不到 pnpm

DSH 插件管理需要 `pnpm`。如果命令明确提示找不到它，可以执行：

```powershell
npm install --global pnpm@11 --ignore-scripts
```

重新打开 PowerShell，确认：

```powershell
pnpm --version
```

然后重试失败的插件安装命令。当前这台电脑已安装 pnpm，通常不需要重复执行。

## 4. 更新 Chrome 扩展

### 4.1 方式 A：直接加载项目目录

适用于你当前在这台开发电脑上的使用方式。

1. 在 Chrome 地址栏输入 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 找到鲸鱼图标的“DSH 当前标签页控制”。
4. 如果它加载自 [项目扩展目录](../chrome-extension/)，点击扩展卡片上的“重新加载”按钮。
5. 点击“详情”，确认版本为 **0.5.0**。

项目扩展目录：

```text
D:\project\dsh_plugin\chrome-extension
```

只有该目录内的文件已经更新，重新加载才会得到新版。当前项目目录已包含 0.5.0 的文件。

### 4.2 方式 B：用 ZIP 更新已解压目录

使用 [Chrome 扩展安装包](../dsh-chrome-extension-0.5.0.zip)。

1. 在扩展管理页暂停旧扩展，避免更新时继续自动化操作。
2. 将新版 ZIP 解压到你原来加载的扩展目录，并选择覆盖旧文件。
3. 确认加载目录根部包含 [扩展清单](../chrome-extension/manifest.json)、[后台脚本](../chrome-extension/background.js) 和 [icons 文件夹](../chrome-extension/icons/)。不要选择 ZIP 文件本身，也不要选择多套了一层的外层目录。
4. 回到 `chrome://extensions`，点击“重新加载”。如果之前关闭了扩展开关，再重新启用。
5. 在“详情”中确认版本为 **0.5.0**。

解压目录应长期保留。Chrome 从这个目录读取扩展，不能在加载后把它删除。

### 4.3 无法直接更新时，移除后重装

1. 打开 `chrome://extensions`。
2. 找到旧的 DSH 扩展，点击“移除”并确认。
3. 保持“开发者模式”开启。
4. 点击“加载已解压的扩展程序”。
5. 选择新版扩展目录。
6. 确认只保留一份 DSH 扩展，并确认版本为 **0.5.0**。

Chrome 可能显示读取网页和调试权限，这是浏览器控制功能需要的权限。Chrome 自带的调试提示不能由插件隐藏；取消该提示可能断开控制。

### 4.4 自动连接

安装或重新加载后，扩展会连接正在运行的 DSH。点击工具栏鲸鱼图标，可以查看连接状态；如果扩展先前被手动暂停，点击“恢复自动连接”。

默认地址：

```text
ws://127.0.0.1:19876/extension
```

正常使用无需打开高级设置，也无需填写令牌。只有你明确修改了 DSH 的 `bridgePort` 时，才需要在扩展高级设置中使用相同端口。

也可以打开 [本地连接状态页](http://127.0.0.1:19876/setup) 检查 DSH 本地桥是否启动。

## 5. 处理旧版已经打开的窗口和副本

0.5.0 不再自动创建独立控制窗口，但旧版留下的窗口不会被升级过程自动关闭。

建议按以下顺序整理：

1. 先释放正在进行的网页控制。
2. 保留你正常使用的原 JumpServer 标签页。
3. 检查旧版的“被接管 / 已释放”副本，确认其中没有需要保留的表单输入或进行中的远程任务。
4. 手动关闭不再需要的多余副本，以及已经空闲的旧控制窗口。
5. 使用下面第 6 节的语句重新测试接管。

不要仅凭“网址相同”就判断可以关闭，原页面和副本本来就可能使用同一个网址。

如果提示“已有副本身份无法验证”，按提示定位并关闭旧副本，再重新选择原标签页。插件会在身份不确定时停止，不会直接接管任意同网址页面或创建第二份。

## 6. 更新后的验证

### 6.1 验证自动连接与接管

在原浏览器窗口打开并登录 JumpServer，例如 [当前 JumpServer](http://jumpserver.ii-ai.tech/luna/)。在 DSH 对话中发送：

> 帮我查看当前 JumpServer 页面，只测试接管和读取，不执行终端命令。

预期结果：

- 自动找到目标原页面。
- 同一窗口内出现一个后台副本，或复用此前已存在的副本。
- 受控副本显示“【被接管】”和页面角标。
- 没有新开浏览器窗口，也不会自动切走你正在操作的标签页。
- Agent 返回页面文字；如果后台截图不可用，返回明确说明。

### 6.2 验证副本只创建一次

在同一会话中连续发送两次：

> 继续查看刚才的 JumpServer 页面。

预期仍使用原来的同一个副本，不再新增标签页。

随后要求：

> 释放当前网页控制，但保留页面。

再请求接管同一原页面，预期复用现有副本。换到其他 DSH 会话时，如果副本仍被前一会话占用，应提示先释放，而不是新建另一份。

### 6.3 验证原页面与焦点

在 Agent 读取或操作副本时，你可以继续使用原窗口其他标签页。预期不会发生窗口置前、标签页来回切换或标签页移动。

Chrome 首次建立调试连接时可能显示原生提示条。它与插件反复切换标签页是两种不同现象；如果每次普通读取都切页，先确认 Chrome 扩展确实已经更新，而不只是更新了 DSH 插件。

### 6.4 验证 JumpServer 终端

后台副本不继承原页面的实时 SSH 会话，需要在副本中重新选择资产并打开终端。以“中核战舰”为例，可以发送：

> 在受控副本中打开“中核战舰”，先确认主机名，再只读查看 Kubernetes 当前 context，不更新镜像。

检查终端实际输出后再判断成功。输入已发送、截图为空或浏览器连接正常，都不能单独证明远程命令执行成功。

## 7. 日常使用方式

| 需求 | 可直接发送给 Agent 的指令 |
| --- | --- |
| 查看页面 | 查看当前 Chrome 里的 JumpServer 页面 |
| 明确网址 | 接管 `http://jumpserver.ii-ai.tech/luna/` 对应的原标签页 |
| 重复读取 | 继续读取刚才的页面，复用已有副本 |
| 查看 Kubernetes | 在副本终端只读查看当前 context、节点和命名空间 |
| 释放控制 | 断开当前网页控制，保留标签页 |
| 关闭副本 | 关闭当前受控副本，保留原标签页 |

副本是同网址的独立页面，不复制导航历史、未提交表单、JavaScript 内存或现有 WebSocket / SSH 会话。它与原页面共享网站账号，因此副本提交表单、退出登录或执行发布，仍会影响真实系统。

Kubernetes 镜像更新的命令模板与检查步骤见 [JumpServer / Kubernetes 指南](./jumpserver-kubernetes.md)。

## 8. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 仍然要求填写配对令牌 | Chrome 仍在运行旧版扩展。确认只安装一份 DSH 扩展，更新后重新加载，并核对版本 |
| 扩展一直等待连接 | 确认 DSH 正在运行、插件已启用、扩展未暂停；查看本地状态页是否能打开 |
| 没有浏览器工具 | 确认 DSH 插件安装在实际使用的 profile 中，且启用成功 |
| 仍然新开窗口或多次复制 | 确认 DSH 和 Chrome 两端都为 0.5.0；关闭确认不再使用的旧版副本后重新测试 |
| 提示副本正在被其他会话使用 | 回到占用它的会话释放控制，再继续；无需再次复制 |
| 提示旧副本身份无法验证 | 按提示关闭旧副本，保留原页面，再请求接管 |
| 有多个同等匹配的 JumpServer 页面 | 告诉 Agent 选择具体候选，或先整理多余原页面；不要让它猜测 |
| 截图不可用，但能读到页面文字 | Chrome 没有绘制后台副本。继续使用页面文字，或手动选中受控副本后再截图 |
| 纯 Canvas / WebGL 终端输出读不到 | 没有可读 DOM 时需要截图。截图不可用就先手动选中副本；不要因此重复发送已提交命令 |
| Chrome 扩展提示加载失败 | 检查所选目录是否直接包含扩展清单；ZIP 必须先解压；查看扩展管理页的具体错误 |
| 本地端口 19876 被占用 | 确认是否同时运行多个 DSH profile；使用对应 profile，或为其中一个配置其他端口并同步扩展设置 |
| 更新后没有立即生效 | Chrome 扩展要点击“重新加载”；DSH 则按安装结果判断是否需要重启 |

## 9. 回退与卸载

### 9.1 回退

先保留当前安装包和之前确认可用的版本，再进行回退。为避免浏览器端与 DSH 端行为不一致，两部分应使用对应版本。

DSH 侧回退示例：

```powershell
dsh plugin --profile web remove dsh-browser-use
```

再安装你自行保存的上一版本安装包（项目目录只保留当前 0.5.0，旧安装包需要你提前备份）：

```powershell
dsh plugin --profile web add "<你保存的旧版本安装包路径>.tgz"
```

Chrome 侧使用该版本对应的扩展目录或 ZIP，重新加载后确认版本。不要在原目录混放不同版本文件；可解压到独立目录，再通过扩展管理页加载。

**旧版本不包含本次空白副本、重复复制和窗口切换的修复。** 通常应先按第 8 节排查，而不是直接回退。

### 9.2 完全卸载

1. 在对话中释放当前浏览器控制。
2. 打开 `chrome://extensions`，移除 DSH 扩展。
3. 在 PowerShell 执行：

```powershell
dsh plugin --profile web remove dsh-browser-use
```

卸载不会回滚先前提交的网页或 Kubernetes 操作。原页面和已经保留的副本可由你按需要手动关闭。
